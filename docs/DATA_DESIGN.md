# DATA_DESIGN — 데이터 분리 전체 목록 + 맵 저장 형식 설계 (초안, 2026-10-12)

> 상태: **승인됨(2026-10-12)** — PR A~D 4개로 진행, 글자는 고정 문구만. 진행: **A 완료(v63)** · **B 완료(v64)** · **C 완료(v65)** · **D 완료(v66)**
> 기준 코드: v62 (PR #4, heroes/skills/monsters.json 분리까지)

앞으로 만들 기능: ① 스토리 스테이지 ② 보스 디펜스 모드(내 던전 꾸미기 = 맵 편집기) ③ 공용 맵 공유 ④ 랭크 1:1 온라인.
이 네 가지가 공통으로 필요로 하는 것: **"코드를 안 고치고 파일만 바꿔서 새 내용을 만들 수 있는 구조"** 와 **"남이 만든 파일을 믿지 않고 검사하는 장치"**.

## 2. 맵 저장 형식 설계 (맵 편집기·공용 맵 공유용)

### 2-1. 원칙
1. **버전 번호**: 모든 파일 맨 위에 `format`(파일 종류)과 `version`(형식 버전). 형식이 바뀌면 version 을 올리고, 게임은 옛 버전을 새 버전으로 **자동 변환(마이그레이션)**. 모르는 새 버전은 거부.
2. **ID로 연결**: 파일끼리는 **이름표(ID)로만** 서로 가리킴(내용 복사 금지). 예: 맵 → `champion: "gron"`, `ruleset: "standard"`. 스테이지 → `map: "gron_maze"`.
3. **맵과 규칙 분리**: 맵 파일엔 **지형·배치만**. 피해량·체력 같은 숫자는 규칙 묶음(ruleset)에. → 같은 맵을 일반전/랭크전(정규화 규칙)에 그대로 쓸 수 있고, 맵 공유로 수치를 조작할 수 없음.
4. **검증기**: 남이 만든 맵은 **믿지 않는다**. 불러오기 전에 반드시 검사. 같은 검사 코드를 게임(불러올 때)·도구(테스트)·나중에 서버(랭크·공유 업로드)가 함께 씀.

### 2-2. 맵 파일 예시 (빈센토 공장, 실제 값)
```json
{
  "format": "pdr-map",
  "version": 1,
  "id": "vince_factory",
  "name": "자동화 로봇 공장",
  "author": "official",
  "champion": "vince",
  "ruleset": "standard",
  "size": { "w": 30, "h": 30 },
  "tiles": [
    "..............................",
    "...(30줄, 한 줄에 30글자)...",
    "###...###..###..###...###....."
  ],
  "spawns": {
    "boss": { "x": 12, "y": 2 },
    "generator": { "x": 18, "y": 2 },
    "heroes": [ { "x": 12, "y": 28 }, { "x": 15, "y": 28 }, { "x": 18, "y": 28 } ]
  },
  "objects": []
}
```
- `tiles`: 한 글자 = 한 칸. `.` 바닥, `#` 벽. (나중에 `~` 물, `^` 가시 바닥 등 **글자만 추가**하면 확장 가능 — 글자표는 형식 문서에 고정)
  - 편집기에서 만들기 쉽고, 사람이 눈으로 봐도 지도처럼 보이고, 변경 기록(GitHub)에서 어느 칸이 바뀌었는지 보임.
- `spawns`: 시작 위치. 보스는 3×3 이라 **가운데 칸** 기준.
- `objects`: 편집기로 미리 놓는 것(상자, 함정, 벽 Lv, 구덩이 등) — 디펜스 모드용. 각 항목 `{ "type": "chest", "x": 5, "y": 9 }`. v1 공식 맵은 비어 있음.

### 2-3. 그론 랜덤 미로
```json
{ "format": "pdr-map", "version": 1, "id": "gron_maze", "name": "장난감 미로 던전",
  "champion": "gron", "ruleset": "standard", "size": { "w": 30, "h": 30 },
  "generator": { "type": "maze" },
  "spawns": { "boss": { "x": 15, "y": 2 }, "heroes": [ ... ] }, "objects": [] }
```
- `tiles` 대신 `generator` → 매 판 지금처럼 랜덤 미로(동작 동일).
- 공유하고 싶은 "마음에 든 미로"는 편집기에서 **굳히기(tiles 로 저장)** 하면 고정 맵이 됨.

### 2-4. 규칙 묶음 예시 (`rulesets/standard.json`)
```json
{ "format": "pdr-ruleset", "version": 1, "id": "standard", "name": "기본 규칙",
  "heroAp": 3, "clericApMax": 12, "heroMovesPerTurn": 2,
  "boss": { "gron": { "hp": 420, "ap": 6, "move": 3 }, "vince": { ... } },
  "chest": { "max": 6, "spawnChance": 0.2, "life": 12, "gold": [[3,1],[4,3],...], "item": {"scroll":0.10,"gem":0.25,"potion":0.30} },
  "crystal": { ... }, "mapWallHp": 20,
  "win": { "type": "defeat_boss" } }
```
- 영웅/스킬/몬스터 파일은 "유닛 사전"(이름·기본값), 규칙 묶음은 "이 판의 규칙". 랭크 정규화는 규칙 묶음 하나만 새로 만들면 됨.

### 2-5. 검증기가 확인하는 것 (맵 v1)
1. 형식: `format == "pdr-map"`, `version` 이 아는 버전인지(옛 버전이면 변환)
2. 필수 항목·자료형: id(영문·숫자·`_`·`-`, 64자 이내), name(40자 이내), size, tiles **또는** generator 중 정확히 하나
3. 크기: v1 은 30×30 만. tiles 가 정확히 30줄 × 30글자, 허용 글자만
4. 테두리: 맨 바깥 줄·칸은 벽 또는 바닥 규칙 준수(지금 게임은 테두리 밖 이동 불가 — 바깥은 자동 벽 취급, 검증기는 스폰이 테두리에서 1칸 이상 안쪽인지 확인)
5. 연결: `champion`, `ruleset`, objects 의 `type` 이 **존재하는 ID**인지
6. 스폰: 맵 안, 바닥 칸, 보스 3×3·발전기 3×3 이 벽/서로와 겹치지 않음, 용사 3명 서로 다른 칸
7. **길 확인**: 용사 시작 칸에서 보스까지 **걸어서 갈 수 있는 길**이 있는지(편집기로 막힌 던전을 만드는 것 방지 — 공정성 핵심)
8. 배치 제한: objects 수가 규칙 묶음의 최대치 이하(예: 상자 ≤ 6), 같은 칸 중복 금지
9. 크기 제한: 파일 64KB 이하(공유 악용 방지)
- 결과: `통과` 또는 **한국어로 무엇이 왜 틀렸는지 목록**(편집기에서 그대로 보여줄 수 있게)
- 구현: 검증기는 **자바스크립트 한 벌** (`game/lib/validate.js`) → 게임·테스트 도구(node)·나중 서버(Node.js)가 같은 코드 사용

### 2-6. 랭크 1:1 대비
- 대전 시작 시 양쪽이 쓰는 **맵 ID + 규칙 묶음 ID + 데이터 버전(파일 내용 지문/해시)** 을 서로 확인 → 다르면 시작 안 함(데이터 조작·버전 불일치 방지).
- 최종적으로는 서버가 같은 검증기·같은 규칙으로 판정.
